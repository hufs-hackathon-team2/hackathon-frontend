# 기능명세서 변경사항

구현하면서 명세와 달라진 부분, 새로 정해진 규칙을 모았습니다.
원본 명세서에 반영이 필요합니다.

---

## 1. S52 퀘스트 진행 → 퀘스트 완료 축하 팝업

**변경 전** S52는 퀘스트 3일 체크리스트를 관리하는 화면

**변경 후**

- 3일 체크리스트는 **S50 퀘스트 홈** 안으로 들어감
- S52는 3일차를 체크한 순간 뜨는 **완료 축하 팝업**
- 화면 전환 방식은 `modal`

한 화면에서 시작·체크·포기까지 끝나는 편이 이동이 적어서 이렇게 정했습니다.

## 2. CY 06 사이클 히스토리 (S32) — 범위 축소

**변경 전** 달력 + 사이클 클릭 시 분석 팝업

**변경 후** 지난 사이클 **목록 조회만**

각 항목에 표시하는 내용:

```
n번째 사이클
시작일 ~ 종료일 · 지속일
PLUS Log n일 · 퀘스트 n회 · 최고 연속 n일
```

P1 항목이고, 목록만으로도 누적 성과가 충분히 전달돼서 상세 팝업은 제외했습니다.

## 3. CY 02 사이클 달력 (S30) — 표시 규칙 확정

명세에 "휴식기 밴드"만 있어서 나머지를 정했습니다.

### 밴드 (날짜 배경)

| 구간 | 색 | 범위 |
|---|---|---|
| 활동기 | 진초록 `#4A6B4E` | 사이클 시작일 ~ 종료일 |
| 휴식기 | 회녹색 `#C9CCC0` | 마지막 기록 다음날 ~ 사이클 종료일 |

**휴식기는 사이클당 한 번, 맨 끝에만 생깁니다.** 상태머신상 휴식기 판정과 동시에 사이클이 닫히기 때문에, 중간에 며칠 비어도 그건 휴식기가 아닙니다.

### 점 (날짜 아래)

| 그날 한 일 | 색 |
|---|---|
| PLUS Log만 | 흰색 `#FFFFFF` |
| 퀘스트만 | 노랑 `#E8C547` |
| 둘 다 | 연두 `#8CB369` |

점은 하루에 **하나**입니다. 달력 라이브러리가 밴드(`period`)와 여러 개의 점을 같이 못 그려서, 색으로 세 상태를 구분합니다.

달력 아래에 범례를 답니다.

## 4. CY 03 사이클 분석 (S31)

### 상태

```
IDLE     요청 전. 인사이트·자주 기록한 활동이 잠김
PENDING  분석 중. 버튼 비활성
DONE     내용 공개
```

### 잠금 표현 변경

**변경 전** 요청 전 모자이크 처리

**변경 후** 내용 자리에 `분석을 요청하면 볼 수 있어요` 문구

리액트 네이티브에 블러가 기본으로 없고, 흐린 글자를 억지로 보여주는 것보다 문구 쪽이 읽기 명확합니다.

### 3회 제한

- **횟수 판정은 서버가 합니다.** 프론트는 버튼을 막고 남은 횟수를 보여주기만 합니다
- 횟수는 **사이클마다 따로** 셉니다 (새 사이클 시작 시 0)
- 조회(GET)는 횟수를 차감하지 않습니다

## 5. CY 05 재개 화면 (S40) — 진입 조건 확정

명세에 "조건부 자동 팝업"으로만 되어 있어 조건을 명확히 합니다.

```
1. 퀘스트·PLUS Log 를 7일 이상 안 하면 휴식기 판정
2. 판정과 동시에 진행 중이던 사이클이 닫힘
3. 이후 사용자가 PLUS Log 를 등록하거나 퀘스트를 시작하면
   → 그 순간 새 사이클이 시작되고 재개 화면이 뜸
```

**홈 진입 시점이 아니라, 휴식기 이후 첫 활동 시점에 뜹니다.**

띄우는 곳이 두 군데입니다.

| 화면 | 시점 | 담당 |
|---|---|---|
| S21 기록 입력 | 저장 성공 후 | 홍소담 |
| S50 퀘스트 홈 | 퀘스트 시작 후 | 한서연 |

## 6. 확인이 필요한 항목

아래는 명세 안에서 값이 서로 맞지 않거나 빠져 있는 부분입니다. 확정이 필요합니다.

### 성장 포인트

퀘스트 완료 시 얻는 점수가 문서 안에서 `+3`, `+9`, `+15` 로 다르게 적혀 있습니다. 하나로 정해야 합니다.

현재 화면 구현은 사이클 결과 경험치를 `PLUS Log 1일당 1점 + 퀘스트 1회당 9점` 으로 계산하고 있습니다.

### PLUS Log 하루 1개

하루에 기록을 하나만 남길 수 있는지, 여러 개 남길 수 있는지가 명세에 없습니다. 달력 점 표시와 연속 기록 계산이 여기에 걸립니다.

## 7. 백엔드에 필요한 응답 (신규)

화면을 만들면서 필요해진 항목입니다.

### 사이클 분석

```
POST /cycles/{id}/analysis
  요청 접수만 하고 즉시 응답 (분석에 1~4분 소요)
  4번째 요청이면 거절

GET  /cycles/{id}/analysis
  status   PENDING | DONE | FAILED
  result   DONE 일 때 분석 내용
  count    이번 사이클에서 사용한 횟수
```

앱을 껐다 켜도 결과가 유지되려면 화면 진입 시 GET 으로 상태를 받아와야 합니다.

### 재개 화면 판정

PLUS Log 등록 응답과 퀘스트 시작 응답에 아래가 포함되어야 합니다.

```
newCycleStarted   true / false
previousCycle     id, startDate, endDate, logDays, questDone, streak, restDays
```

`newCycleStarted` 가 true 일 때만 재개 화면을 띄웁니다. 프론트가 7일을 세거나 판정하지 않습니다.

### 사이클 요약 공통

여러 화면에서 같은 모양을 씁니다.

```
id, startDate, endDate, status, logDays, questDone, streak, restDays
```

달력을 그리려면 여기에 더해 **날짜 배열**이 필요합니다.

```
logDates    ['2026-08-03', '2026-08-04', ...]
questDates  ['2026-08-04', '2026-08-05', ...]
```
